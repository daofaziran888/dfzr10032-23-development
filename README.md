# 多源数据采集与RPA自动化平台

面向网页抓取、API接入、增量采集、RPA流程编排、数据校验与采集监控的数据工程平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 采样时钟漂移链路

三个模块按“原始读数 → 漂移明细 → 计时事件 → 交班区间”串起来：

1. **采样时钟漂移**（`/api/clock_drift`）：来源表带采样周期、时间容差、跳变阈值、
   补送阈值和接入时间精度；原始读数只有设备序号、设备时刻、接入时点、接入顺序。
   计算时先按设备序号和设备时刻还原时段，接入顺序只用于并列判断，不直接改写
   时间，因此网关补送的旧包会回到它原本的序号位置。判定分五类：
   - `时钟跳变`：设备间隔偏离采样周期，序号连续，接入间隔仍正常，偏移持续存在；
     按累计偏移修正时间并允许继续使用。
   - `缓存补送`：设备间隔与序号正常，但接入滞后或乱序；样本保留原位。
   - `重启交界`：设备序号回到 1、设备时刻回拨；同一设备时刻出现两条不同读数、
     接入只精确到分钟时，交界区间标为待现场核对。
   - `无法断定`：设备间隔与接入间隔同步多出一个采样周期；不修改时间，后续绝对
     时间失去锚点，整段不可按修正时间使用。
   - `采样缺口`：序号不连续；缺口两端分别交付，不跨缺口合并。

   每条明细都保留 `判定依据`、`依据样本`、`修正时间可用性` 与修正后区间。

2. **计时事件**（`/api/timing_event`）：消费漂移明细，一个受影响来源 + 一段采样
   区间生成一条事件，带 `计时影响`、`允许按修正时间继续使用` 和 `待现场核对`。
   `GET /api/log_viewer/timing-events` 是采集日志侧的入口。

3. **交班记录**（`/api/handover`）：按计时事件把同一来源划成 `可交付` / `仅参考` /
   `待核对` 三类互不重叠的区间。已随交班记录移交过的样本不会重复计入；待核对
   区间连同判定依据和依据样本列入下一班清单，可用
   `POST /api/handover/intervals/{id}/resolve` 回填现场结论（确认可交付 / 确认不可用），
   回填不会把相邻已确认时段再算一遍。

对应前端页面：`/clock_drift`、`/timing_event`、`/handover`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 测试

```bash
cd backend
python3 -m pytest tests -q
```

测试覆盖：时钟跳变修正与补送包不改时间、重启交界同刻双读数与分钟精度、
无法断定后整段失去锚点、缺口不合并、计时事件判定依据、交班区间不重叠、
已确认时段不重复计入、现场回填不重算相邻时段。
